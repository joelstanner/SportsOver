# Chess broadcasts

Chess uses the public [Lichess Broadcast API](https://lichess-org.github.io/api/#tag/Broadcasts), verified without authentication on October 2, 2026. This covers over-the-board events carried by Lichess; it is not a directory of every FIDE event or a personal online-game tracker.

## Setup and display

Like PDGA, Settings offers browse-or-paste discovery, saved watches, inclusion, ranking, removal, and a followed-player view. Browse current broadcasts, or paste a tournament/round/game broadcast link (or eight-character ID), then load it and watch its current round or pin a specific round. Each saved watch is one rotation entry. Separate tournament sections can be watched independently. No manual chess watch is preselected. Automatic elite discovery is on by default when no preference has been saved; an explicit off choice is preserved.

During live rounds, the tournament banner shows all broadcast matchups in board order through a three-row scrolling viewport: White and Black, titles, published tournament points, last broadcast clocks, move number, side-to-move highlight, and completed board results. Missing clocks or points show a dash. The footer includes live/finished board counts, time control, and broadcast delay. Points remain tournament totals, not the current game result. Standings failures leave matchups visible and label the points as stale or unavailable.

Outside live play, the tournament banner shows the top 10 players by published tournament points, with Lichess's tiebreak rank determining order among equal scores. It scrolls vertically through a three-row viewport. Choose **Top 3 · static** for a fixed leaderboard; this setting applies to standings, while live rounds always include all broadcast boards. **Add player banner** creates an independent rotation entry for a player in the same tournament/round; its inclusion, order, locks, and duration remain independent. From a player banner, **Add tournament banner** adds the corresponding live-matchups/standings view. Player banners enter rotation only after a player is selected, and leave it again if that selection is cleared. Existing watch identities and player selections are retained.

Standings come from Lichess's public player totals, including custom scoring and grouped tournament scores. They always reflect current tournament totals, even when the matchup banner is pinned to an older round. Broadcasts without published scores show an unavailable message; current-board results are never presented as tournament standings. A standings request failure retains previously received totals with a stale label while player matchups can keep updating.

The desktop process fetches standings through a restricted local route because Lichess's website standings endpoint does not allow the app's custom browser origin. Requests still use the shared refresh cache, serialization, and rate-limit cooldown.

The followed-player view shows the pairing, ratings/federations when supplied, last broadcast clocks, side to move when a position is supplied, and result. Selection follows FIDE ID across rounds, or exact name when no FIDE ID exists. An absent player falls back to standings. Both layouts fit the existing 460 × 88 scorebug in the 472 × 100 desktop/OBS window. Vertical scrolling completes within the banner's configured rotation duration and preserves its phase through score refreshes. Hover/focus pauses the list in place and leaving resumes it; reduced-motion mode uses manual scrolling only.

Automatic current-round watches retain a stable tournament watch key across rounds. They use an ongoing round first, then the latest scheduled started unfinished round, the nearest scheduled future round, the latest completed round, or the default/first round. A future round shows Upcoming with its scheduled start and the current tournament standings; pinned watches stay on their chosen round. Live requires at least one unfinished board with a recorded move; an ongoing round flag or unplayed pairings alone do not qualify. Intermediate completion, a later round past its scheduled start awaiting its first move after an earlier completed round, and gaps with finished boards but no active games show Break. Final-round completion is Final. Pinning a round makes its completion Final even if the tournament continues. Watches remain in normal rotation until disabled or removed; top-favorite mode uses the first included chess watch. Existing queue modes, durations, exclusions, locks, and Live mode apply.

Chess and disc-golf breaks use the configured **Final** rotation duration, unless that banner has a duration override. Active play uses **Live** timing; team-sport interruptions retain **Live** timing. A freshly polled tournament state also updates its queue state and rotation timer.

## Automatic elite watches

The shared engine checks the directory on startup and every 15 minutes while SportsOver is running, even when score refresh settings are longer. It finds up to eight nearby official high-tier (4) and best-tier (5) tournaments, prioritizing best-tier events. Normal-tier (3) and unofficial events are excluded. The date window extends seven days forward/backward; already followed active tournaments remain through round breaks and directory rollover (bounded to sixteen with retained events). These tiers are Lichess's editorial classification, not an inferred player ranking. Coverage depends on its public broadcasts.

Discovered events are saved in Settings' **Automatic watch list**, separately from manual watches. The list updates as events are posted and retires old events after a healthy discovery. Partial outages can add confirmed events but cannot erase previous watches. Turn **Included** off to exclude an automatic entry; **Keep watch** makes it a manual watch so you can select a player or keep the event indefinitely. Manual watches take precedence over matching discoveries. Pausing automatic discovery preserves the saved list and manual player choices but removes automatically selected entries from rotation and Live mode.

All eligible live events and round breaks rotate in normal mode. Live mode excludes individual tournaments during round breaks and automatically includes them again when play resumes. Detected completions remain for one hour in normal rotation, or the configured Live mode retention; newly found finals are offered as a recent-final fallback rather than treated as observed finishes. When no active or retained event remains, the upcoming/recent-final/hide fallback selects the appropriate event. Top-favorite mode limits automatic chess suggestions to one, in addition to the top manual watch. Searches stop when the app is closed and resume on launch; no background OS job is installed.

PDGA retains its existing 15-minute Elite Series/Major discovery and selected-event behavior. Its discovered MPO/FPO divisions now appear in the same saved automatic watch list. An existing PDGA on/off preference is preserved.

## Selective second-tier suggestions

Chess and PDGA each have a **Find select second-tier live tournaments** setting, enabled by default and independent of elite auto-follow. It offers up to three additional tournaments per sport in **Available games**, labeled **Second tier** with the selection reason. Suggestions do not enter normal rotation automatically; use **Add** or **Watch tournament / Watch division**. **Add** persists the tournament/division identity in rotation and loads it directly after restart, independently of discovery, shortlist ranking, or second-tier settings. Existing saved Add selections are recovered the same way. Remove or Undo clears that selection; an explicitly disabled saved watch remains disabled. A saved watch retains its normal behavior when second-tier discovery is turned off. PDGA respects the existing MPO/FPO checkboxes (at most six division banners across three tournaments).

Chess considers only Lichess official normal-tier (3) broadcasts whose directory round is ongoing, then verifies actual unfinished play and a broadcast field with at least two GM/WGM players or four GM/WGM/IM/WIM players. Distinct player identities are counted once. Qualifying events are ranked by grandmaster count, then total master count. These are field-strength heuristics, not a FIDE prestige classification. Unofficial broadcasts, weak fields, and unstarted pairings are excluded.

PDGA considers pro A-tier individual stroke-play events, including A/B events only when the pro tier is A. Only live MPO/FPO divisions qualify; B/C tiers, amateur-only events and doubles are excluded. The top five published player ratings prioritize the field (division-relative to 1000 for MPO and 900 for FPO). A-tier sanctioning supplies the prestige signal; unknown ratings are ranked last. It does not infer prestige from an event's name.

Both directories are checked every 15 minutes. To bound provider traffic, each scan examines at most twelve candidate tournaments before selecting three. This is a selective shortlist, not a complete ranking of every tournament. Shortlisted scores keep the normal refresh cadence. Round breaks and finals stop being offered as new live suggestions; save a watch to follow an event throughout. Outages retain last received suggestions with a stale label, and a healthy scan retires old suggestions.

Verified October 3, 2026: neither provider's directory supplies a dependable structured prize-pool field. The app does not invent purse amounts or equate PDGA added cash with the total purse. Selection uses [Lichess official tiers](https://github.com/lichess-org/lila/blob/master/modules/relay/src/main/RelayTour.scala), player titles/ratings, and [PDGA tier standards](https://www.pdga.com/rules/competition-manual/505). High-purse tournaments without qualifying feed metadata can still be watched manually.

## Data and refresh

- `GET /api/broadcast/top`: browse current broadcasts; fifteen-minute cache.
- `GET /api/broadcast/{tourId}`: event metadata and round schedule.
- `GET /broadcast/{tourId}/players`: published player scores, games played, and tiebreak ranks.
- `GET /api/broadcast/-/-/{roundId}`: games, results, positions and clock snapshots. SEO slugs can be replaced with `-`.

All responses are JSON, fitting the existing shared refresh cache and sole desktop engine. Default intervals are 30 seconds live, 60 upcoming, and 300 idle/final. Tournament metadata remains on the live refresh cadence until all posted rounds are completed so newly posted rounds can be discovered. Rotation, native output and OBS reuse the engine. Requests within a page are serialized and in-flight requests deduplicated. The shared refresh cache spaces actual Lichess network requests at least one second apart; cached reads remain immediate. HTTP 429, including errors thrown by the cache or returned through the desktop standings bridge, pauses further requests for at least one minute and honors longer Retry-After values. Failed directory/shortlist discovery retries after the cooldown instead of waiting for the next fifteen-minute scan. Freshly inspected matchups are reused even if a later discovery request is rate-limited. Routine failures use the existing backoff. Last successful event data is retained with an explicit STALE label, including upcoming pairings when the feed becomes unavailable.

Clocks use Lichess preview centiseconds and show the received snapshot; no local ticking or engine evaluation is added. Source broadcast delay is preserved and labeled when supplied. Missing clocks show a dash. Unchanged moves or clock snapshots alone do not prove a pause: long thinks and delayed feeds are possible, and the public preview has no definitive game-pause signal. Unknown results are never converted to draws, and missing FEN does not invent a side to move. The full broadcast is linked for boards and analysis. Private broadcasts require authorization and are outside this integration.

## Verification

`npm test` includes provider normalization, round transitions, reference validation, request serialization, rate-limit cooldown, stale recovery, and saved configuration. `npm run test:chess` exercises browse/watch/player selection, persistence, queue locks, round advancement, clocks, scaling, stale recovery, final results, missing-player fallback, mixed-sport rotation and Demo lab with fixture data. `npm run test:chess:desktop` checks the native and OBS outputs in an isolated Electron instance with fixture feeds.

`node tests/browser/chess-matchups.cjs` checks live tournament boards, results, clocks, published points, missing/stale standings, scrolling, and transitions back to standings.

`npm run test:elite` and `npm run test:elite:desktop` verify saved chess/PDGA automatic lists, tier filtering, exclusions, keeping watches, player preferences, persistence, and pausing discovery. The desktop check confirms Settings and OBS reuse one directory search. Unit checks advance time to verify newly posted events are found at the next 15-minute search.

`node tests/browser/second-tier.cjs` verifies labeled suggestions in Available games, adding to rotation, keeping a manual watch, and persisted opt-out without losing manual watches. Provider tests cover qualification, field ranking, caps, live status, cadence, stale recovery, and division controls.

`node tests/browser/tournament-banners.cjs` checks separate tournament/player entries for both sports, saved top-three/top-ten choices, published chess points, vertical scrolling, fixed banner dimensions, and reduced-motion behavior.
